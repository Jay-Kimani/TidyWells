About Tidywells

Tidywells is a small open-source project that makes Canadian oil and gas regulator data easier to work with. It has three parts: a Python package that loads and cleans public well and production files into one consistent layout, a browser tool for fitting a decline curve to a well, and plain-language analysis built on the same code.

Why

Alberta, Saskatchewan and British Columbia all publish useful data, but in different layouts, with leading-zero IDs that spreadsheets damage, duplicate rows, and codes that need a lookup table. Most of the work is cleaning. We would rather do that once, in the open, and show how reliable the simple tools built on top really are.

Principles

  • Your files stay yours. The tools work on files you download. We do not host regulator data, and the web tool never uploads anything.
  • Show the work. Every analysis links to the code that produced it, and the Methods page lists the sources and rules.
  • Say what it can't do. Results are illustrative, not for reserves reporting or investment decisions, and we publish the limits next to the results.

How this is made

Tidywells is built by one person with AI assistance. I use Claude, an AI model from Anthropic, to help write code, draft pages and posts, and build the site. I would rather say that plainly than leave you to guess.

What that means in practice:

  • Numbers come from code, not from a chat. Every figure is calculated by scripts from public Petrinex and BC Energy Regulator files. An AI model does not type figures in or estimate them.
  • Published figures are re-checked automatically. A script recomputes the figures on the monthly snapshots and the home page from the open dataset on every change, and the build fails if any differ. The results are on the Open data page.
  • The code is open. The package, its tests and the site generators are on GitHub, so you can rerun any result yourself. Releases are archived on Zenodo with a permanent DOI: 10.5281/zenodo.23969867.
  • Our forecasts are graded in public. The scorecard logs forecasts before the data exists, and What didn't work lists the mistakes and methods that lost.
  • A person is accountable. I decide what gets published, and I list mistakes and fixes on the Corrections page.
  • AI writing can still be wrong. Wording can be too confident or repetitive. If a sentence or a number looks off, open an issue.
